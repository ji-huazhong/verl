注册使用 Bridge 公共 API，无需向已安装包硬塞模型名称。provider 复用其 Qwen3VL 包装，在 decoder 中替换混合 MoE / HC / PLE / QSA 层。HF 权重导入和输出映射处理 GDN 分组投影、PLE shard、跨 rank expert owner 和普通 gamma，避免错误 zero-centered BF16 转换吞掉小更新。

PLE 大表按请求固定在 host；训练式大表路径仍保留用于测试。每次 packed forward / recompute 维护文档边界、ngram context 与异常清理。CP 支持只开放已验证组合；最终长跑是 CP1。MTP 和 LoRA 关闭，文本任务不提供 vision loss，QSA 硬 top-k 不通过 GRPO 获得选择梯度。

03 / 精度问题不是单一开关造成的

初始固定 token 的 BF16 平均差约 0.104。定位先固定输入、权重和路由，再逐层观察 HC、GDN、QSA、PLE、MoE；另外比较同后端重复加载、prefill/decode、sleep/refit 和调度控制。不同口径的误差不能拼成一条“0.104 → 0.008”的单因素收益曲线。

阶段 / 证据定位结论最终处理
HC 中间值Megatron 保留 FP32；vLLM 在 norm / down / SiLU / up 等边界写回 BF16。多次舍入可沿残差放大。保留训练侧精度策略，修改 vLLM 的 Qwen HC 路径；独立开关和算子回归。
GDN 输入投影qkvzba 合并 TE GEMM 与拆分 GEMM 的归约几何不同。PyTorch 的低精度归约开关不控制 TE；隔离输入上拆分结果更接近 FP64 并与 vLLM 对齐。verl 中拆 qkvz / ba，保持 TE；同步映射、梯度、分布式 checkpoint。卷积和 gated norm 保留 FP32 中间值。
相同模型重载漂移Q/K L2 norm 的不同 kernel 线程 / 编译配置导致 rsqrt 差异。固定同份输入能复现加载差别。固定 FP32 rsqrt 实现；两次完整加载 2,500 个 token logprob 逐位一致。独立 Q/K GPU 回归通过。
MoE / QSA路由差别和已选 block 的累加顺序会放大 BF16 差异；不能仅凭误差跨越 QSA budget 就认定 top-k membership 错误。启用 verl 已有 R3；QSA canonical order 保留选中集合。按逻辑上下文分桶继续观察尾部。
PLE sleep / refit 状态丢失权重未变不等于运行状态未变。vLLM model state 在 weights pool 内创建，sleep(2) 后丢失 context offsets，refit 不恢复，导致 n-gram ID / 查表改变。独立 runtime pool。32 条真实请求验证 PLE 状态，6 项真实 CuMem 生命周期回归通过。
修复后仍见约 0.02048 回放差异步调度的 batch / prefill / decode 路径没有保持一致，不能把它全部归因于残留 PLE bug。固定调度后，32 requests、每阶段 4,096 logprobs、6 阶段同 vLLM 输出逐位一致。不能据此宣称跨后端逐位相等。
真实 DAPO GRPO同一 prompt multiset 的独立采样 cohort：均差约 0.03794 → 0.01132，响应并非同一组 token，因此不是严格单因素同输入 A/B。第二步约 0.01136 后获准长跑；最终 100 步均差范围 0.007287–0.010918。
候选与被排除的解释

FlashQLA 和 vLLM router FP32 输出仍是可选实验，不属于最终默认组合。单改 β 的 0.00615 → 0.00654 不能证明稳定退化或根因。vLLM #59945 的 head_dim fallback 在本 checkpoint 显式 head_dim=256 时未触发。Miles 的公开曲线仅提供生成响应误差的参考量级；没有将不同数据、并行和采样条件下的曲线当作严格复现实验。

04 / 哪些修改超出了 verl

所有修改材料保存在 verl；运行时仍有外部依赖要求。“落在 verl”指源代码、补丁和重建入口可追踪，并不意味着 stock wheel 自动具备修复。详细文件、作用范围和应用顺序见 外部依赖补丁说明。

归属变化上游反馈类别
vLLMmodel-state runtime pool / PLE sleep(2) 状态保留正确性 bug，优先独立反馈；覆盖其他 model state / sleep backend 后提交
vLLMQwen HC、GDN convolution FP32 中间值精度策略；分别附误差、吞吐、显存对照，不统称算法 bug
vLLMTorch 2.10 stable ABI 回移及 UVA keepalive / deleter特定旧 ABI 兼容；产物仅面向指定 Torch/CUDA
Megatron-BridgePython <3.13 → <3.14 与本地版本号只有包装元数据修改，无模型运行算法 bug patch
Megatron-CoreDP-sharded CPU optimizer restore 修复正确性 bug；现由 verl 中 Core 0.19.2 shim 接管类方法，需上游最小复现
TE / Transformers / FLA本次不修改其安装源码；GDN 变更在 verl 子类，沿用 TE GEMM / FLA不应提交成这些项目的已证实通用 bug
vLLM extensionverl 中显式选择的 QSA 排序 hook确实修改运行时外部行为，须在评审中披露；保留原 top-k 集合

准备工具先验证固定 HEAD 与干净工作树，再在一次性源码树中应用完整补丁；构建入口检查隔离 venv、目标 ABI 和修改文件哈希。依赖 wheels 未写入 Git。Bridge 与 vLLM 的原始版权和来源声明保留。

05 / 最终长跑配置与资源

数据DAPO-Math-17k 固定 revision，去重 / 去冲突后 17,391 条；AIME-2024 去重后 30 条验证。仅检查精确文本重合，不保证语义去污染。
训练目标train_batch_size = ppo_mini_batch_size = 128，n=8，即每 update 1,024 responses；prompt 2K / response 8K；100 步，LR 1e-6，KL coef 0.001。
128 × H100 80GB16 节点 × 8 卡。Actor/Ref TP4 / PP2 / EP8 / ETP1 / CP1，dense DP16 / expert DP8。SP + 全层 recompute + CPU optimizer offload。
推理16 个节点内 TP8 replica，每个 PP1 / DP1 / EP1；eager，R3，QSA canonical order，HC/GDN FP32 + PLE state fix。
验证 / 保存val_before_train=false，50 / 100 步验证和保存；validation n=4，最终 acc/mean@4=0.925（30 题，未做训练前验证，不能据此算验证提升）。
依赖Python 3.13 / Torch 2.10.0 / CUDA 13.1，vLLM main 6e517b15 + hcgdnfp32.plestate；Core 0.19.2、Bridge 0.6.2+nebula1、Transformers 5.16.1、FLA 0.5.2。

128 卡早期热步为 1,326 / 1,317 秒，64 卡对照热步约 1,803 秒。末 10 步平均总耗时 1,144 秒（19.1 分钟），其中 generation 959 秒、actor update 89 秒；此时 rollout 已占主要时间。训练越往后输出长度和阶段开销会变化，不能把所有加速都归因于并行策略。
